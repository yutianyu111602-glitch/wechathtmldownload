# PCUI GPT-5.4 Image Runbook

> 2026-04-23 UI-only 口径更新：本文是废弃的 gpt-image-2 历史 runbook，不再作为当前 UI 路线。当前 UI 设计与工程唯一事实源是 `docs/superpowers/specs/pcui-final-ssot.md`；当前 UI-only 执行 track 是 `docs/superpowers/specs/2026-04-23-pcui-ui-only-ralph-prd.md`、`docs/superpowers/plans/2026-04-23-pcui-ui-only-consolidation-plan.md`、`.omc/ralph/pcui-ui-only-consolidation/prd.json` 和 `.omc/state/pcui-ui-only-ralph-state.json`。不得从本文恢复 image-first 工作流。

## Purpose

This runbook restores the intended workflow for the PCUI redesign:

1. generate page images first with `gpt-5.4` + `gpt-image-2`
2. review and pick direction
3. feed the selected module images back into a master design board prompt
4. review and pick the master direction
5. only then modify the Electron UI

This means UI coding should pause until image outputs are reviewed.

## Required Model Pair

- text model: `gpt-5.4`
- image model: `gpt-image-2`

## Generation Order

Generate in this order, because each later page should inherit the shell and density decisions from the earlier pages.

0. Run access gate: `npm run pcui:image:verify`
1. Full Shell Baseline
2. Task Bus
3. Collection & Accounts
4. Archive & Download
5. Process & Export
6. LLM Substate
7. Artifacts & Review
8. Master Design Board from selected module screenshots

## Per-Page Output Count

For each page, generate exactly 3 variants:

- Variant A: balanced density, safest production direction
- Variant B: denser operator-console direction
- Variant C: more restrained Win11 direction

Do not vary shell structure between variants.
Only vary:

- density
- header compression
- toolbar grouping
- table emphasis
- inspector emphasis

Do not vary:

- navigation model
- status bar presence
- run console presence
- overall pane architecture

## Prompt Source

Use:

- `docs/superpowers/specs/2026-04-22-pcui-gpt-image-2-prompts.md`
- executable source: `tools/pcuiGptImage2Prompts.mjs`

Useful commands:

- dry-run prompt export: `npm run pcui:image:prompts`
- model access check: `npm run pcui:image:verify`
- real image generation: `npm run pcui:image:generate`

`npm run pcui:image:generate` runs `--execute --include-master`: it generates module screenshots first, then feeds the first successful screenshot from each module into the master design board request as image references.

## Run Instructions

For each page prompt:

1. prepend the shared direction block
2. append the page-specific block
3. append the negative prompt addendum
4. request a straight-on app screenshot in `16:10`

## Review Checklist

Reject any image that shows one or more of these:

- overview dashboard homepage
- hero banner
- centered marketing composition
- floating card grid as main structure
- glass panels or glow borders
- purple or pink AI gradients
- command bar filled with global path forms across all pages
- inspector used as generic explanatory content
- bottom console missing or visually de-emphasized into a footer afterthought
- LLM page that looks like chat, assistant UI, prompt hero, or model marketing

Accept only images where:

- main work surface is table-first
- right inspector clearly follows selection
- bottom run console reads as a real event surface
- status colors are visible but controlled
- titlebar and commandbar feel like desktop chrome, not webpage header bands

## Required Deliverables After Generation

After generating images, create one short image-review note with:

1. chosen shell baseline
2. chosen variant per page
3. chosen master board
4. reusable token decisions
5. per-page implementation notes
6. anti-web findings that still need code-side enforcement

## Access Gate And Failure Semantics

The generation command must not fake success.

- If no API key is available, stop after `prompt-manifest.json`.
- If model access fails, record the error in the terminal and do not write fake image paths.
- If a generation request fails mid-run, write `image-generation-manifest.json` with the successful images and the failing record.
- If the master board reference-image request fails, keep the module image results and mark only `99-master-design-board` as failed.
- Do not switch models silently. `gpt-image-2` is the default model for this plan.

## Implementation Gate

Do not start the next large UI refactor pass until the image review note exists.

Small cleanup already made in the codebase can remain, but new structural UI edits should wait for image selection.
