# ATLAS 星图重设计规格

日期：2026-07-10  
状态：设计已确认，等待书面规格复核  
目标页面：`apps/weekly_activity_miniprogram/pages/atlas-starmap/atlas-starmap`

## 1. 目标

把 ATLAS 星图从“画布上叠放搜索、筛选和大卡片”重构为手机端的“宇宙探索地图”：

- 星图始终是主界面，不被详情列表长期遮挡。
- 节点、光环、连线、明暗和标签都表达 ATLAS V2 的真实字段。
- 用户先看懂实体结构，再逐步进入一跳关系、时间、城市和证据。
- 保留现有搜索、邻域下钻、回溯、关系路径、DJ 详情、分享、足迹和本周种子能力。
- 不增加新依赖，不改生产数据库，不在本任务中上传、提审或公开发布小程序。

## 2. 当前事实

### 2.1 页面与运行数据

- 页面使用微信小程序原生 `<canvas type="2d">`。
- 基础包当前为 240 个节点、640 条边。
- 邻域包覆盖 240 个基础节点，每个节点 40 条邻域记录，共 9,600 条。
- 页面已有本地邻域、远端 `/api/v1/weekly/atlas/neighborhood`、路径 `/api/v1/weekly/atlas/path`、人物 `/api/v1/weekly/atlas/artist`、分享 `focusId` 和探索回溯能力。
- 现有三项镜头中只有“实体关系”可用；“未来活动”和“DJ 轨迹”长期展示未完成提示，削弱首屏可信度。

### 2.2 ATLAS V2 字段事实

本规格只读核对：

`tools/atlas_rebuild/_sandbox_entity_merge_apply_20260622_0045/atlas_serving_v2_enriched_merged.sqlite`

核心表和字段：

- `subject`：`subject_type`、`display_name`、`city_primary`、`event_count`、`relation_count`、`source_count`、`confidence`、`first_seen_at`、`last_seen_at`、`public_state`。
- `relation`：`relation_type`、`weight`、`same_event_count`、`b2b_count`、`first_seen_at`、`last_seen_at`、`sample_evidence_json`。
- `dj_profile`：`origin_city`、`roles_json`、`styles_json`、`genre`、`bio_snippet`、`affiliations_json`、`venue_count`、`org_count`。
- `venue_profile`：`city`、`district`、`venue_type`、`resident_dj_count`、`event_count` 等。

当前 V2 共 75,015 个实体：39,363 DJ、21,935 系列、8,578 厂牌/组织、5,139 场地。实体指标是强长尾：

| 字段 | P50 | P90 | P99 | 最大值 |
| --- | ---: | ---: | ---: | ---: |
| `event_count` | 1 | 9 | 115 | 4,308 |
| `relation_count` | 7 | 36 | 284 | 4,860 |
| `source_count` | 1 | 8 | 101 | 1,688 |

关系前 50,000 条只读样本中，`weight` 的 P50/P90/P99 为 26/139/585，且样本全部有首末时间和证据字段。V2 还有 3,928 个名称跨实体类型碰撞，单一名称最多同时出现在四种实体类型中。

字段限制：

- `city_primary` 在全体实体中大量缺失，不能作为默认主色；场地城市较完整，可用于城市镜头。
- `confidence` 对 DJ 与其他实体的生产方式不一致，不能跨类型直接比较。
- DJ `styles_json` 覆盖较高但大小写和同义词未完全归一，不作为第一阶段主视觉编码。
- 当前小程序 `atlas_starmap.js` 只携带 `u/n/t/c/x/y/s/col`；原始事件数、关系数、来源数、首末时间没有进入运行包，基础边也没有保留 `weight`。

## 3. 已确认的产品方向

### 3.1 布局：星海主舞台

- 全屏 Canvas 是第一视觉层。
- 顶部只保留紧凑标题、点亮数/足迹入口和单行搜索。
- 筛选、关系路径、复位收进右侧垂直工具轨。
- 删除首屏长期占位的未完成镜头按钮。
- 城市和时间作为工具轨中的二级镜头，不与默认实体结构争抢首屏。

### 3.2 三段式交互

1. **总览态**：完整画布；只显示高信息量节点标签。
2. **聚焦态**：点击节点后，选中节点和一跳邻域高亮；底部出现约 104rpx 的窥视卡。
3. **探索态**：上拉后出现最高 45vh 的底部抽屉；展示关系筛选、下一跳、时间、城市、证据摘要和动作。

完整 DJ 档案继续进入现有 `pages/artist/artist`，不把人物详情重新堆进星图抽屉。进入关系路径模式时自动收起抽屉，只保留起点提示，避免遮挡第二个节点。

## 4. 数据视觉编码

### 4.1 节点

实体类型同时使用形状和颜色，不能只依赖颜色：

| 实体 | 形状 | 基础色 |
| --- | --- | --- |
| DJ | 实心圆 | `#7FD4FF` |
| 场地 | 六边形 | `#FFCF6B` |
| 厂牌/组织 | 菱形 | `#B794F6` |
| 系列 | 空心环 | `#2DD4BF` |

视觉量：

- 核心尺寸：`eventScore = clamp(log1p(event_count) / log1p(115), 0, 1)`；基础半径为 `3.5 + 5.5 * eventScore` 画布像素，再乘受限缩放系数。P99 以上不继续放大。
- 外环：`relationScore = clamp(log1p(relation_count) / log1p(284), 0, 1)`；外环间距为 `3 + 4 * relationScore`。P90 增加第二层弱环，P99 增加第三层弱环。
- 证据刻度：`source_count` 只在聚焦态和探索态显示，按 `1 / 8 / 101` 三档绘制 2/4/8 个短刻度；不在总览态制造噪声。
- 选择态：`#A7FF26` 只用于当前焦点、激活工具和主操作，不作为实体类型色。
- `confidence` 不做跨类型全局视觉编码；只在适用的详情语境中显示。

### 4.2 连线

- 线宽：`weightScore = clamp(log1p(weight) / log1p(585), 0, 1)`；基础线宽为 `0.35 + 1.65 * weightScore` 画布像素，选中一跳边额外增加 `0.45`。
- `b2b`：琥珀色实线。
- `collab`：冷蓝实线。
- `resident_at` / `held_at`：青绿色实线。
- `signed_to` / `presented_by`：紫色短划线或弱实线。
- 未选中总览边低透明；选中节点的一跳边提升对比度。
- `last_seen_at` 只在“时间镜头”控制明暗；默认结构镜头不因关系较旧而隐藏真实历史关系。
- 关系证据和 `same_event_count` / `b2b_count` 进入抽屉摘要，不直接铺在画布上。

### 4.3 城市与时间镜头

- **城市镜头**：只为有可信城市的节点绘制城市星域/锚点；缺失城市归入“未标注”，不猜测。
- **时间镜头**：`last_seen_at` 越近越亮，`first_seen_at—last_seen_at` 在聚焦态形成时间跨度摘要；默认不持续闪烁。
- 两个镜头都是辅助阅读模式。默认仍是“结构优先”。

## 5. 语义缩放与标签

- Z0 总览：只标注选中节点和按 `0.55 * eventScore + 0.45 * relationScore` 排名的少量核心节点。
- Z1 邻域：显示选中节点及一跳邻居标签；其余节点只保留形状。
- Z2 近景：允许显示关系类型、城市或时间短标签。
- 标签有不透明深色底和细边框，避免落在连线上失去可读性。
- 同名实体必须在标签或窥视卡中补充类型，例如 `OIL · 场地`、`OIL · 厂牌`。
- 标签密度按屏幕空间和缩放级别计算，不按固定节点数量硬塞。

## 6. 页面结构

### 6.1 WXML

`atlas-starmap.wxml` 调整为四层：

1. Canvas。
2. 紧凑顶部命令区。
3. 右侧工具轨和轻量 HUD。
4. 聚焦窥视卡 / 探索抽屉 / 路径结果面板。

现有关系筛选、分享、关系路径、DJ 详情、回溯和足迹入口继续复用。未完成镜头不再占据首屏。

### 6.2 WXSS

- 背景保持深墨色 `#03070B` / `#05070D`。
- 正文 22–24rpx，关键节点名称 28–30rpx，辅助信息 18–20rpx。
- 触控目标最小 72rpx；关闭、筛选和路径入口必须有明确按压态。
- 圆角以 8–14rpx 为主，底部抽屉可以使用 18–24rpx 顶部圆角。
- 不使用玻璃拟态、紫粉渐变、装饰性霓虹、卡片套卡片或无语义光晕。
- 光晕只服务于节点层级和选择状态。

### 6.3 JavaScript 状态

新增最小页面状态：

- `sheetState`: `hidden | peek | explore`。
- `viewLens`: `structure | city | time`。
- `zoomTier`: `overview | neighborhood | detail`。
- `toolPanel`: `"" | filters | lenses`。

复用现有 `selected`、`explorationTrail`、`relatedFilter`、`pathMode`、`pathResult`。不引入新的状态管理层。

Canvas 绘制新增小型纯函数：

- 节点指标归一与半径计算。
- 实体形状绘制。
- 关系线宽/颜色计算。
- 标签候选评分与碰撞规避。
- 城市镜头和时间镜头的辅助绘制。

这些函数留在当前页面文件附近，避免为单页过早建立通用图形框架。

## 7. 运行包扩展

修改 `tools/atlas_rebuild/export_mp_starmap_bundle.py`，从 V2 只读导出以下紧凑字段：

节点：

- `ec`: `event_count`
- `rc`: `relation_count`
- `sc`: `source_count`
- `fs`: `first_seen_at`
- `ls`: `last_seen_at`

边：

- 保持前三位 `[srcIndex, dstIndex, relationType]` 兼容现有代码。
- 第四位增加 `weight`。
- 其他证据字段不进入基础包，避免体积膨胀；在选中节点后通过现有接口/邻域记录读取。

保留旧字段 `s` 作为旧包和动态邻居的回退值。新字段缺失时页面仍可使用 `s`、邻域 `w/rs` 和现有 inspector 正常渲染。

生成器必须同时更新 JSON 源副本和小程序运行用 JS 包，二者的 schema、节点数、边数和紧凑字段一致。

## 8. 数据流与回退

1. 页面载入基础 JS 包，立即渲染 240 节点总览。
2. 用户选择节点时，先用本地邻域包生成窥视卡和一跳关系。
3. 若本地邻域不足，调用远端 neighborhood；失败时保留本地结果，不清空画布。
4. DJ inspector 异步加载；失败时保留节点指标、关系列表和基础动作。
5. 路径接口失败时只更新路径面板，不重置选中节点和视角。
6. 城市/时间字段缺失时隐藏对应行，不显示“0”或推测值。

## 9. 性能边界

- 基础节点仍为 240，基础边仍为 640。
- 单次下钻沿用最多 18 个动态邻居；切换焦点时复用或回收上一焦点的动态显示状态。
- 触摸移动和缩放通过现有 `requestAnimationFrame` 绘制周期合并，不在每个触摸事件中创建新对象数组。
- 标签碰撞计算只针对当前可见标签候选，不针对全部节点做全量布局。
- 不引入 WebGL、Three.js 或第三方图引擎；完整 Web 星图继续属于 Web 页面。

## 11. 验收标准

- 首屏不再显示未完成镜头占位。
- 未选择节点时，Canvas 至少保留除顶部命令区外的绝大多数视野。
- 选择节点后默认只出现窥视卡；详情抽屉必须由用户主动展开。
- 抽屉最大高度 45vh，关闭或收起后恢复完整触控区域。
- 四种实体可在灰度或色弱条件下通过形状区分。
- 节点核心、外环和基础连线都来自 V2 明确字段或明确回退值。
- 城市缺失不会被渲染为猜测城市；跨类型同名不会只显示裸名称。
- 搜索、邻域下钻、回溯、关系筛选、路径、分享、足迹和 DJ 详情无回归。
- 无新依赖，无数据库写入，无上传/提审/发布副作用。

## 12. 明确不做

- 不把星图改成列表页。
- 不把完整人物档案塞进星图抽屉。
- 不在本阶段制作任务资源、经济系统或完整游戏循环。
- 不把城市颜色设为全局主编码。
- 不使用全屏持续粒子动画或高频脉冲。
- 不修改 ATLAS V2 生产数据、CloudRun 部署状态或微信发布状态。
